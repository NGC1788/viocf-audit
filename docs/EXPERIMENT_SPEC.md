# 사전고정 실험 명세

## 연구질문

1. 동일 MIDI와 동일 초기 latent에서 주법·강약 개입이 의도한 출력 변화를 만드는가?
2. 비목표 특징 변화가 실제 바이올린의 자연 변동범위를 초과하는가?
3. 주법과 강약의 interaction이 실악기의 interaction과 일치하는가?
4. technique-aware CC1 보정이 held-out 악기에서도 response gap을 줄이는가?
5. 미래의 CC1 조건이 분기 이전 오디오로 새거나, pizzicato에 물리적으로 불가능한 후기 에너지를 만드는가?

## 가설

- H1: p<mf<f RMS 단조성은 평균적으로 나타나지만 technique별 포화와 크기 오차가 존재한다.
- H2: duration/register OOD에서 pitch·timing leakage가 실제 기준보다 커진다.
- H3: technique×dynamics interaction의 모델 분포는 실연주 분포와 다르다.
- H4: technique-aware monotonic calibration은 response alignment를 개선하면서 pitch/onset을 보존한다.
- H5: full-window 생성기는 delayed branch의 미래 CC1을 분기 이전 오디오에 누출할 수 있다.

## 반사실 효과

특징 벡터를 `z`라고 하고 기준을 sustain/mf로 둔다.

```text
Delta_T = z(t, mf) - z(sustain, mf)
Delta_D = z(t, d)  - z(t, mf)
I(t,d)  = z(t,d) - z(t,mf) - z(sustain,d) + z(sustain,mf)
```

모든 delta는 model에서는 prompt×initial-noise 내부, real에서는 prompt×performer×violin×take 내부에서 계산한다.

## Primary endpoint

1. Effect Alignment cosine 및 magnitude ratio
2. Human-calibrated Excess Leakage
3. Human-calibrated Compositionality Gap

RMS–CC1 Spearman 은 secondary endpoint 다.

**미구현 항목의 지위** — 아래 둘은 이 저장소에 구현돼 있지 않다. 구현 전까지
결과·발표에서 언급하지 않는다(약속만 하고 없는 지표는 그 자체가 결함이다).
- **FAD**: 오디오 품질 지표. 이 연구의 질문(제어 충실도)과 직교하며, 참조 분포 선택이
  결과를 좌우해 논쟁을 부른다. 넣으려면 참조 코퍼스를 명세에 먼저 고정해야 한다.
- **VioPTT accuracy**: [VioPTT](https://arxiv.org/abs/2509.23759) 는 저자 일부가
  VIOLET 과 겹치고 둘 다 합성 학습자료를 쓴다. 그대로 쓰면 순환 평가다. 쓴다면
  **독립적인 주법 검출기**(예: MERTech, arXiv 2310.09853)와 병행해 일치할 때만 인용한다.

## 통계 단위

- frame이나 note를 독립 표본으로 세지 않는다.
- primary generalization unit은 prompt다.
- model seed와 real take/violin은 prompt 내부 반복이다.
- prompt-level **2단계(hierarchical) 부트스트랩**을 사용한다: prompt 를 복원추출한 뒤
  뽑힌 prompt 안에서 관측치를 다시 복원추출한다 (`metrics.bootstrap_mean_ci`).
  클러스터만 재표집하는 1단계 부트스트랩은 클러스터 내부 변동을 무시해 CI 를 좁게 낸다.
- 세 global endpoint(CEA/HCEL/CG)만 confirmatory 로 두고, 특징별 누출 비교는
  **Holm-Bonferroni 보정**한다 (`metrics.holm_adjust`). p 값은 prompt 단위
  부호뒤집기 순열검정으로 낸다 (`metrics.cluster_permutation_pvalue`) — prompt 내부
  상관을 깨지 않기 위해서다. 결과는 `metrics_summary.json` 의
  `leakage_per_feature_tests` 에 원시 p 와 보정 p 가 함께 기록된다.

## 개정 이력 (Preregistration amendments)

사전고정 명세는 **데이터 수집 시작 전에만** 고칠 수 있고, 고칠 때는 이유와 근거를 남긴다.
아래 개정은 전부 **실측 데이터가 한 건도 수집되기 전**에 이루어졌다(오디오 0개 상태).

### 2026-08-26 개정 1 — F0 주 backend 를 SwiftF0 에서 yin 으로

**원래**: "논문 분석의 F0 backend 는 SwiftF0 0.1.2 로 고정한다."

**문제**: primary endpoint 중 하나가 "강약 개입 시 음정이 얼마나 새는가(cents)"인데,
SwiftF0 는 **같은 음 안에서의 음정 차이를 측정하지 못한다.** 합성 신호(2.5 s)로 실측:

| 음 | 주입한 차이 | SwiftF0 측정 | yin 측정 |
|---|---|---|---|
| G3 | 10 c | **0.0 c** | 9.8 c |
| A4 | 50 c | 66.1 c | 50.1 c |
| G5 | 25 c | **−0.3 c** | 25.7 c |
| G5 | 50 c | 21.9 c | 49.5 c |

SwiftF0 는 거친 음정 격자에 스냅되어 10 cents 이동을 0 으로 읽는다. 이 상태로 실험했다면
조건 간 음정 차이가 항상 0 근처로 나와 **"VIOLET 은 음정 누출이 없다"는 거짓 음성**이
headline 결론이 됐을 것이다.

**개정**: 역할을 분리한다.
- SwiftF0: voiced 판정 + 사전고정 비교값 `f0_cents_error_configured` (버리지 않고 함께 보고)
- yin(연속값, 격자 없음): 지표가 사용하는 `f0_cents_error`, `f0_mod_std_cents`, 비브라토
- 두 backend 값을 같은 물리량 열에 **절대 섞지 않는다.** 행마다 backend 를 기록한다.

**논문 보고 방식**: 두 backend 결과를 모두 싣고, SwiftF0 의 격자 한계를 분석기 검증
절(section)에 명시한다. 회귀 방지 테스트는 `tests/test_analyzer_ground_truth.py`.

### 2026-08-26 개정 4 — z 단위의 정의를 명확히

`1 z` = **같은 조건을 다시 연주했을 때의 흔들림(조건 내 IQR 의 중앙값)**.
기존 구현은 조건 전체를 뭉친 IQR 을 썼는데, 그건 "p 부터 f 까지 전체 폭"이라 훨씬 크고
모델의 이탈을 실제보다 작아 보이게 만든다. 명세가 선언한 "실연주 자연 변동" 과도 다르다.
조건 내 반복이 없어 후퇴한 특징은 `robust_feature_scales` 에 기록되어 감사 가능하다.

### 2026-08-27 개정 6 — 추가 4주법의 지위를 "탐색"으로 정정

**개정 5 의 오류**: 늘린 4개 주법을 "모델 vs 가상악기 축으로 감사한다"고 적었으나,
**가상악기 기준선은 이 저장소에 구현된 적이 없다.** 근거 없는 비교를 명세에 적어 둔 것이고,
그대로 발표하면 "그 가상악기 데이터는 어디 있느냐"는 질문에 답할 수 없다.

**정정**: 추가 4주법은 **generator-only 탐색 축**이다.
- manifest 의 `analysis_tier` 열로 구분한다
  (`real_counterfactual_primary` / `generator_only_exploratory`).
- `run_metric_suite` 와 `fit_technique_calibration` 은 primary 행만 사용한다.
  탐색 행은 CEA/HCEL/CG 어느 headline 에도 들어갈 수 없다.
- `pilot`·`full` 프로파일은 실악기 대응 4주법만 생성한다(`model_techniques_for_profile`).
  탐색 주법은 `expanded` 와, 명시적으로 요청한 sweep(`--include-exploratory-techniques`)에서만 나온다.
- 탐색 행의 용도는 **대리모델(surrogate) 학습과 실패 영역 탐색**이다.
  "VIOLET 이 이 주법에서 제어를 흘린다"는 주장은 실악기 기준선이 생기기 전까지 하지 않는다.

가상악기 기준선을 정말 넣고 싶다면 별도 개정으로 **데이터 출처·라이선스·렌더 절차**를
먼저 명세에 적고 구현한 뒤에 한다.

### 2026-08-27 개정 7 — 샘플링 스텝 축을 실행 경로에 연결

개정 5 에서 스텝 축은 manifest 와 MIDI 까지만 만들어졌고 **실행기가 그 축을 무시**했다.
그대로 돌렸으면 6개 스텝 조건이 전부 기본값 30 으로 렌더돼 축이 통째로 무의미해진다.

`verify_violet_run.sh` → `collect-violet` 까지 이어지고, 렌더 로그의
`effective_sampling_steps` 를 manifest 기대값과 대조해 어긋나면 `pairing_pass` 가 실패한다.


## 개정 8 — 렌더 실패 판정을 활성 구간 검출기로 (데이터 수집 후, 지표 산출 전)

expanded 전수 QC(18,432 클립)를 돌린 뒤의 정정이다.

**무엇이 틀렸나.** 무음 판정 경계를 peak −35 dBFS 로 잡으면서 "표본에서 정상 셀과
실패 셀이 완전히 분리되고 그 사이가 비어 있다"고 근거를 달았다. 전수 분포는
−65 부근의 얕은 최소를 지나 −30 까지 단조 증가하는 연속 꼬리이고, 검출기가
무음이라 한 클립과 소리가 있다고 한 클립의 peak 범위가 겹친다. **어떤 단일 peak
경계로도 검출기 판정을 재현할 수 없다.** 표본 384개로 본 "분리"는 실재하지 않았다.

**어떻게 고쳤나.** 지표의 제외 기준 1순위를 활성 구간 검출기(`qc_reasons` 의
`near_silence`/`missing_audio`/`non_finite_samples`)로 바꿨다. 이 기준은 조정
상수가 없다 — 어떤 프레임 RMS 도 −60 dBFS 를 넘지 못하면 소리가 없는 것이다.
peak 경계는 QC 미실행 시의 대용으로만 남기고 `PEAK_FALLBACK_DBFS` 로 명시했다.

**전수 결과.** 생성 실패 1,157 / 18,432 = **6.28 %**. 독립적으로 뽑은 표본
추정치(24/384 = 6.25 %)와 일치한다.

## 개정 9 — low_snr 은 품질 게이트가 아니다 (같은 시점)

전수 QC 에서 실패 5,795건 전부에 `low_snr` 이 붙었고, `clipping` 은 0건이었다.
`min_snr_db: 30` 은 실연주 녹음의 방 소음을 전제로 정한 값인데, snr_db 분포는
+5~+45 dB 에 몰려 봉우리가 +35 다. **기준선이 분포 한가운데를 자른다** — 이상치
검출이 아니라 임의 절단이다.

주법별 실패율도 pizzicato 52.0 % vs trill_major 14.2 % 로 갈리는데, 이것이
디코더 노이즈의 성질인지 짧은 주법을 벌주는 측정 인공물인지는 SNR 을 신호항과
노이즈항으로 분해해야 판정된다(`scripts/audit_snr_criterion.py`).

`qc_pass` 는 지표에서 행을 거르지 않으므로 결과가 오염되지는 않았다. 다만
"31.4 % 실패"라는 요약 숫자는 그대로 인용하면 안 된다 — 생성 실패 6.28 % 와
임계값 절단 25.16 % 는 완전히 다른 것이다.

## 개정 10 — 임베딩 C2ST 에 크기/방향 대조 추가 (모델 전용 분석, 녹음 전)

모델 전용 임베딩 분석 첫 실행에서 강약 C2ST 가 0.822(양성 대조 0.983)로 나왔다.
처음 해석은 "강약이 음색을 바꾼다"였는데, **그 해석의 근거가 성립하지 않는다.**

"MERT 는 음량에 눈이 멀었다"는 이 저장소의 측정치는 **코사인 유사도** 1.0000 이다.
코사인은 벡터의 크기를 무시한다. 음량이 임베딩의 노름만 키우고 방향을 그대로 두면
코사인은 1.0000 이지만, 원좌표를 쓰는 C2ST 는 그 크기 차이만으로 완벽히 갈라낸다.
즉 원좌표 C2ST 가 높다는 사실만으로는 음색 변화를 주장할 수 없다.

**대조를 추가했다.** L2 정규화로 크기를 지운 뒤 같은 C2ST 를 다시 돌린다.

  원좌표 높음 + 정규화도 높음  ->  방향이 바뀌었다 = 진짜 음색 변화
  원좌표 높음 + 정규화 ~ 0.5   ->  크기만 바뀌었다 = 사실상 볼륨 손잡이

강약별 임베딩 L2 노름도 직접 출력한다.

정답을 심은 합성 데이터 두 벌로 검증했다(둘 다 노름은 강약에 따라 단조 증가):
  크기만 바뀐 경우  정규화 후 0.596  -> '볼륨 손잡이'로 올바르게 판정
  방향도 바뀐 경우  정규화 후 0.994  -> '음색 변화'로 올바르게 판정
노름 단조성만으로는 두 경우가 구분되지 않는다. 정규화 C2ST 가 판별한다.

**앵커 편향도 함께 고쳤다.** B(직교성)·C(합성성)에서 `combinations(techniques,2)[:6]`
을 쓴 탓에 6쌍 전부가 harmonic 을 앵커로 하고 있었다. 두 절은 C2ST 를 쓰지 않고
평균만 계산하므로 비싸지 않다 — 전 주법 조합을 양방향(`permutations`)으로 본다.
양성 대조 쌍도 목록 앞부분만 자르지 않고 흩어 고르도록 바꿨다.


## 개정 11 — 무음 판정 세 번째이자 정본: 절대 기준 (지표 산출 전)

`audit_snr_criterion.py` 전수 결과가 **2차 기준(활성 구간 검출기)도 오염돼 있음**을
드러냈다. 검출기가 '무음'이라 판정한 1,157 개의 peak 분위수가
50 % −58.9 / 75 % −27.0 / 95 % −15.1 / 최대 −10.6 dBFS 였다. 무음일 수 없는 값이다.

**기제.** `detect_active_region` 의 문턱은 `max(noise_rms · 10^(12/20), 10^(−60/20))`
이고 `noise_rms` 는 클립 앞 0.35 초의 RMS 다. 첫 음은 0.75 초에 들어오므로 그 구간은
비어 있어야 하는데, VIOLET 이 거기에 무언가를 내면 문턱이 따라 올라가 어떤 프레임도
넘지 못하고 **소리가 큰 클립이 무음으로 판정된다.** 합성 오디오로 재현했다:
−15 dBFS 로 또렷이 울리는 클립에 −25 dB 앞구간을 주입하니 검출기가 '무음'이라 했고,
절대 기준은 올바르게 '소리 있음'으로 판정했다.

**정본 기준.** `scripts/rescore_silence.py`

    silent  <=>  max_t (프레임 RMS)(t)  <  −60 dBFS      (46 ms 창, 10 ms 홉)

앞구간을 보지 않는다. 상수는 문턱 하나이고 그건 "어떤 46 ms 구간도 −60 dBFS 를
넘지 못하면 소리가 없다"는 절대 진술이다.

**따라서 '생성 실패 6.28 %' 는 잠정 수치이며 상한이다.** 앞서 표본 추정 6.25 %(peak
< −50 dBFS)와 수치가 맞았던 것은 서로 다른 것을 재고 우연히 겹친 결과다 — 경계
−50 에서 두 기준의 판정이 389건 어긋난다. 재판정 결과로 대체해야 한다.

**부수적 결과.** 앞 0.35 초에 소리가 새는 클립의 존재 자체가 관측 결과다.
악보상 그 구간에는 아무 일도 일어나지 않아야 한다. 재판정 스크립트가 앞구간 RMS
분위수와 −60 dBFS 초과 비율을 함께 보고한다.

## 개정 12 — low_snr 은 측정 인공물로 확정 (전수 분해)

`min_snr_db: 30` 을 근거로 한 실패 25.16 %p 는 **모델 결함이 아니다.**
SNR 을 신호항과 노이즈항으로 분해한 전수 결과:

| 층 | 신호항 변동폭 | 노이즈항 변동폭 |
|---|---|---|
| technique | 9.79 dB | 1.16 dB |
| dynamic_label | 6.06 dB | 0.69 dB |
| pattern | 4.47 dB | 1.95 dB |

**디코더 바닥 노이즈는 사실상 일정하다**(중앙값 −70.0 dBFS, 주법 간 1.16 dB).
변동은 전부 신호항에서 온다. 듀티비(소리 나는 시간 비율)와 SNR 의 상관은
r = +0.555 이고, 듀티비 구간별 실패율은 70.3 % → 46.8 % → 2.7 % 로 급락한다.
즉 `low_snr` 은 "짧은 주법"을 벌주는 지표다. 품질 게이트로 쓸 수 없다.

`snr_db` 중앙값은 35.4 dB 이고 기준 30 dB 는 26.8 분위에 있다 — 이상치 검출이
아니라 임의 절단이다. **VIOLET 디코더의 바닥 노이즈 −70.0 dBFS 는 보고할 모델
성질로 남긴다**(실연주 녹음의 방 소음과 성격이 다르다).

## 개정 16 — 지연 분기 실행 가능성 판정 (무음 34.4 % 에 대한 대응)

개정 13 에서 `delayed_long x pizzicato` 무음률 34.4 % 를 보고 "검정력을 다시
계산해야 한다"고 적었다. 그 계산이다.

**클립 손실은 그룹 손실이 아니다.** `delayed_branch_strict_model_leak` 은
noise_group 하나 안에 강약이 2개 이상 남아 있으면 그 그룹을 쓴다. 설계는
2 주법 x 3 강약 x 32 replicate = 192 클립이고, 그룹은 (주법 x replicate) 로 64개다.

무음이 그룹 안에서 어떻게 분포하느냐에 따라 남는 그룹 수가 달라진다.
설계상 `noise_group = "<prompt>-rep<NN>"` 이 seed 를 결정하므로 한 그룹의 p/mf/f 는
**같은 초기 latent** 를 공유한다 — 무음이 뭉칠 것이라는 검정 가능한 예측이 나온다.

`scripts/delayed_branch_feasibility.py` 가 그룹별 무음 개수 분포를 같은 주변확률의
이항분포와 대조한다. 양 끝(0개 또는 전부)이 이항보다 많으면 뭉침이다.

정답을 심은 합성 데이터로 검증:

| 시나리오 | 양 끝 관측 vs 기대 | 판정 | 쓸 수 있는 그룹 |
|---|---|---|---|
| latent 가 결정 | 32 vs 10.3 | 뭉침 (정답) | 53 / 64 |
| 렌더마다 독립 | 14 vs 12.2 | 독립 (정답) | 60 / 64 |

**결론: 어느 쪽이든 실험은 성립한다.** 클립 34.4 % 손실이 그룹으로는 6~17 % 손실에
그친다. 대응만 달라진다 — 뭉침이면 replicate 를 늘리면 그룹이 늘고, 독립이면
replicate 를 늘려도 그룹당 결손 비율은 그대로다.

⚠ 이 검정의 귀무가설은 "분기 이전 구간이 조건에 관계없이 **정확히** 같다"이다
(같은 latent + 분기 전 CC1 동일, sample-and-hold). 잡음 있는 평균 비교가 아니라
결정성 확인이므로 통상적 검정력 계산이 그대로 적용되지 않는다. 그룹 수는
'누출 크기의 신뢰구간'을 좁히는 데 쓰인다.

**고침.** `extract_features` 가 무음 판정을 직접 낸다. 이미 오디오를 읽으므로

    frame_rms_max_dbfs   프레임 RMS 최대값 (46 ms 창, 10 ms 홉)
    silent_absolute      frame_rms_max_dbfs < -60 dBFS

영향: 잘못 제외된 1,678건(9.0 %)이 정본 기준 약 4.3 % 로 줄고, **무엇보다 제외되는
클립의 목록 자체가 달라진다**(개정 11 에서 보였듯 두 기준은 −50 부근에서 389건
어긋난다). 지표를 다시 계산해야 한다.

## 개정 19 — 지연 분기 검정에서 측정 불가 그룹이 '누출'로 세어지던 문제

전수 실행 중 `RuntimeWarning: All-NaN axis encountered` 가 두 번 떴다. 원인을 보니
헤드라인 지표의 논리 오류였다.

무음 클립은 분기 전 특징이 NaN 이다. 강약 라벨이 2개 이상 있어도 **값이** 2개가
아니면 spread 를 낼 수 없다. 그 경우 `np.nanmax([nan, nan])` 이 NaN 이 되고
`NaN < 1e-6` 이 False 라서 **자료가 없는 그룹이 '누출 있음'으로 세어졌다.**

이 검정의 주장이 "N개 그룹 **전부**에서 분기 전 구간이 다르다"인 만큼 분모가
오염되면 주장 자체가 부풀려진다.

고침: `measurable` 열을 두어 유한한 spread 가 하나라도 있는 그룹만 판정에
넣는다. 요약도 `noise_groups_measured` / `noise_groups_unmeasurable` 로 나누고
`median_spread` 를 함께 낸다(최대값만 보면 이상치 하나에 휘둘린다).

회귀 테스트 `test_delayed_branch_does_not_count_unmeasurable_groups_as_leaks` 가
causal / leaky / 측정불가 세 그룹을 섞어 넣고 각각의 분류를 확인한다.

p/mf/f 가 같은 latent 를 쓰므로 설계와 일치한다.

쓸 수 있는 그룹: pizzicato 19/32 + sustain 32/32 = **51**. 개정 16 의 예측
(53~60) 범위에 가깝고, 실험은 성립한다. 대응은 '뭉침' 쪽이므로 replicate 를
늘리면 그룹이 늘어난다.

**남은 질문.** 정확히 2개가 무음인 6개 그룹은 '경계선 latent' 다. 거기서 살아남는
쪽이 계통적으로 특정 강약이라면 무음이 latent 만의 문제가 아니라 조건과
상호작용한다는 뜻이다. 스크립트가 그 생존율을 강약별로 낸다.

## 개정 21 — 분기 전 창을 악보 시각에 고정 (헤드라인 수치 재계산 필요)

분기 전 구간이 **검출된 onset** 에 걸려 있었다.

    branch_time = onset_time + branch_offset        # onset_time = 검출된 활성 구간 시작
    pre = [onset_time + 0.04, branch_time - 0.02]

onset 검출이 조건마다 흔들리면 창 자체가 움직인다. 그러면 "분기 전이 다르다"가
**진짜 소리 차이인지 다른 구간을 비교한 탓인지 구분되지 않는다.** 이 저장소의
핵심 주장이 그 지표에 걸려 있으므로 남겨둘 수 없는 모호함이다.

**얼마나 심각한가 — 측정했다.** 분기 전 오디오를 비트 단위로 동일하게 만들고
일부 조건에만 10 ms 선행 신호를 넣어 onset 검출만 흔들었다(참값 spread = 0).

| 기준 | spread |
|---|---|
| 검출 onset | **6.73 dB** (가짜 누출) |
| 악보 시각 | **0.0000 dB** (정답) |

**고침.** `note_onset_s` 와 `branch_offset_s` 는 manifest 값이라 한 noise_group 안의
p/mf/f 가 정확히 같다. 거기에 창을 걸면 모든 조건이 같은 절대 시각을 본다.
`prebranch_abs_rms_dbfs` / `prebranch_abs_centroid_hz` 를 추가하고
`delayed_branch_strict_model_leak` 이 그쪽을 우선 쓰도록 했다.
회귀 테스트 `test_prebranch_window_is_anchored_to_notated_time` 이 고정한다
(그 테스트는 blip 이 실제로 onset 검출을 흔들었는지 먼저 확인한다 — 안 흔들렸다면
아무것도 검증하지 못하기 때문이다).

**영향.** `noise_groups 51 / identical 0 / max_spread 21.1 dB` 는 창 어긋남이
섞인 값이다. 특징 추출부터 다시 돌려야 한다. 방향(0 identical)이 뒤집힐 가능성은
낮지만 **크기는 반드시 다시 재야 한다.**

## 개정 22 — 분기 후 조건이 분기 전 소리의 존재 자체를 결정한다

`delayed_branch_feasibility.py` 실측. 정확히 2개가 무음인 6개 '경계선 latent'
그룹에서 생존이 완벽히 갈렸다.

| 강약 | 분기 후 CC1 | 변화 | 생존 |
|---|---|---|---|
| p | 32 | 64 → 32 (감소) | **6 / 6** |
| mf | 64 | 64 → 64 (**변화 없음**) | 0 / 6 |
| f | 96 | 64 → 96 (증가) | 0 / 6 |

H0(생존이 강약과 무관, 그룹마다 균등)에서 한 강약이 6회 모두 이길 확률
p = 0.0041.

**'변화가 있으면 깨진다'가 아니다.** mf 는 분기 전후가 모두 64 로 아무 변화가
없는데도 죽는다. 갈리는 것은 변화량이 아니라 **분기 이후의 절대 CC1 값**이다.

이것이 왜 중요한가: 같은 초기 latent, 분기 전 조건도 동일한데,
**t = 1.0 s 이후에만 적용되는 제어값이 t < 1.0 s 구간에 소리가 존재하는지를
결정한다.** spread 측정보다 강한 형태의 비인과성 증거다.

⚠ 이 결과는 개정 21 의 창 문제와 **무관하다.** `silent_absolute` 는 클립 전체에
절대 기준을 적용한 값이라 창 정렬에 영향받지 않는다. 재계산이 필요한 것은
spread 크기이지 이 발견이 아니다.

## 개정 23 — 창 수정 후 결과, 그리고 남은 한 곳

### 수정 후 헤드라인 (악보 시각 기준)

    noise_groups_measured      51
    noise_groups_unmeasurable   0
    identical_groups            0
    median_spread   rms  2.03 dB   centroid  120.6 Hz
    max_spread      rms 27.93 dB   centroid 1627.9 Hz

**결론은 유지된다.** 측정 가능한 51개 그룹 전부에서 분기 전 구간이 조건에 따라
다르다. 창을 고친 뒤 최대값은 21.1 → 27.9 dB 로 오히려 **커졌다** — 창 어긋남이
값을 부풀리고 있던 게 아니라 일부에서 가리고 있었다.

**보고할 수치는 중앙값 2.03 dB 다.** 최대 27.9 dB 는 이상치 하나에 좌우되므로
헤드라인으로 쓰면 안 된다. 인과적 생성기라면 0.00 이어야 하는 값이다.

`unmeasurable` 이 0인 이유: `prebranch_abs_*` 는 악보 시각에만 의존하므로 무음
클립에서도 값이 나온다. 무음 클립은 그보다 앞서 지표 계산 단계에서 제외되고,
그 결과 강약이 1개만 남은 그룹은 `len(cells) < 2` 로 걸러진다. 51 은
`delayed_branch_feasibility.py` 가 낸 51 과 일치한다.

### 같은 실수를 한 곳 더 하고 있었다

`delayed_branch_strict_model_leak` 만 고치고 `delayed_branch_metrics` 를 빠뜨렸다.
그쪽은 계속 검출 onset 기준 열을 쓰고 있었으므로, 같은 요약 파일 안에 **서로 다른
정의의 '분기 전'이 섞여 있었다.** 둘 다 악보 시각 기준을 우선하도록 맞췄다.
회귀 테스트 `test_delayed_branch_metrics_uses_notated_window` 가 고정한다 —
두 열에 모순된 값을 심어 두고, 악보 시각 쪽이 쓰이는지 확인한다.

따라서 아래 값은 **창 수정 전 수치이며 재계산해야 한다**:

    pizzicato  future_leak 0.764  post_effect 0.662
    sustain    future_leak 0.575  post_effect 0.462

⚠ 재계산 후에도 `future_leak > post_effect` 가 유지된다면 그건 강한 진술이 된다 —
과거로 새는 양이 의도한 미래 효과보다 크다는 뜻이다. 지금은 아직 말할 수 없다.

### 집계 행의 future_leak 을 채웠다

`sustain_minus_pizzicato` 행의 `future_leak` 이 이유 없이 NaN 이었다. 이 대비가
핵심이다 — 피치카토는 줄을 놓은 뒤라 **정당한 미래 효과가 없으므로** 누출이 더
두드러져야 한다. 차이를 계산해 채웠다.

## 개정 24 — 창 수정 후 지연 분기 결과, 그리고 반론을 막는 대조

### 결과 (악보 시각 기준, 두 함수 모두 수정 후)

| 주법 | future_leak | post_effect | 비 |
|---|---|---|---|
| pizzicato | **1.397** | 0.662 | **2.11** |
| sustain | 0.490 | 0.462 | 1.06 |
| sustain − pizzicato | −0.907 | −0.200 | |

**분기 전 누출이 의도한 분기 후 효과보다 크다** — 피치카토에서 2.11배.
지속음은 1.06 으로 균형에 가깝다.

물리적으로 예측되는 방향이다. 지속음은 t = 1.0 s 에도 활이 줄에 닿아 있어 세기
변화가 정당하지만, 피치카토는 이미 줄을 놓았으므로 그 시점의 세기 변화가
**불가능하다.** 모델은 누출이 가장 불가능한 조건에서 가장 많이 샌다.

창 수정 전 피치카토 future_leak 은 0.764 였다. 검출 onset 기준 창이 누출의
**약 45 % 를 가리고 있었다.**

### 명백한 반론과 그 대조

"피치카토는 감쇠가 급해서 고정 창의 RMS 가 원래 더 민감한 것 아닌가?"
그렇다면 큰 누출은 물리가 아니라 측정 민감도의 산물이다.

주 요인설계 클립은 CC1 이 처음부터 상수라, 같은 창에서 p 와 f 가 다른 것이
**정상**이다(조건이 애초에 다르므로). 그 크기를 분모로 쓰면 민감도가 약분된다.

    누출비 = 지연 조건의 분기 전 |f − p| / 상수 조건의 같은 창 |f − p|

이를 위해 `extract_features` 가 지연 클립이 아니어도 **같은 위치의 창**을 잰다
(`REFERENCE_BRANCH_OFFSET_S = 0.25`, 설계의 `branch_offset_s` 와 같아야 한다).
`prebranch_window_is_branch` 열이 그 창이 실제 분기점인지 기준 창인지 구분한다.

`scripts/leak_ratio.py` 를 정답을 심은 두 시나리오로 검증했다:

| 심은 구조 | 피치카토 누출비 | 지속음 누출비 | 판정 |
|---|---|---|---|
| 진짜 누출 | 0.750 | 0.125 | 반론 기각 (정답) |
| 민감도 산물 | 0.249 | 0.254 | 주법 간 비교 철회 (정답) |

⚠ 분모는 '정당한 차이'이지 잡음이 아니다. 누출비는 검정 통계량이 아니라 **효과
크기의 해석 단위**다. 유의성은 strict 검정(인과적이면 정확히 0)이 낸다.

**주의: 실측 누출비가 아직 없다.** 위 표는 검증용 합성 데이터다. 특징 추출을
다시 돌려야 실제 값이 나온다.

## 개정 25 — 누출비 실측: 민감도 반론 기각 (모델 전용 트랙 완결)

`scripts/leak_ratio.py` 실측 (지연 짝 51, 상수 대조 짝 1,353).

### prebranch_abs_rms_dbfs (중앙값)

| 주법 | 지연(분기 전) | 상수(대조) | 누출비 | n지연 | n대조 |
|---|---|---|---|---|---|
| pizzicato | 4.558 dB | 7.380 dB | **0.618** | 19 | 132 |
| sustain | 1.040 dB | 17.702 dB | **0.059** | 32 | 183 |

### prebranch_abs_centroid_hz (중앙값)

| 주법 | 지연 | 상수 | 누출비 |
|---|---|---|---|
| pizzicato | 120.6 Hz | 403.2 Hz | 0.299 |
| sustain | 70.8 Hz | 391.9 Hz | 0.181 |

### 반론은 기각될 뿐 아니라 **방향이 반대였다**

민감도 반론은 "피치카토는 감쇠가 급해 고정 창 RMS 가 더 민감하다"였다. 그렇다면
피치카토의 **분모(상수 조건의 정당한 차이)가 더 커야** 한다.

실제로는 그 반대다. 상수 조건에서 지속음은 17.70 dB, 피치카토는 7.38 dB —
**피치카토가 오히려 덜 민감하다.** 물리적으로 자연스럽다. 활은 CC1 을 따라
음량이 연속적으로 변하지만, 튕긴 줄의 초기 감쇠는 CC1 에 덜 좌우된다.

즉 원자료에서 피치카토의 누출(4.56 dB)이 지속음(1.04 dB)보다 큰 것은 민감도
때문일 수 없다. 정규화하면 격차가 **10.5 배**로 오히려 벌어진다.

### 해석

**피치카토에서는 '정당한 강약 차이'의 62 % 가 그 원인이 적용되기 전에 이미 나타나
있다.** 지속음은 5.9 % 다.

지속음은 t = 1.0 s 에도 활이 줄에 닿아 있어 미래 세기가 과거와 물리적으로
연결돼 있다(연주자도 미리 준비한다). 피치카토는 이미 줄을 놓았으므로 그런
연결이 존재할 수 없다. **연결이 물리적으로 불가능한 쪽에서 누출이 10 배 크다.**

결론은 여전히 "물리 법칙 위반"이 아니라 **"VIOLET 은 전 구간 확산이라 구조적으로
비인과적이며, 실시간·대화형 제어에 사용할 수 없다"** 이다. 이제 그 진술이
민감도 반론을 통과한 수치로 뒷받침된다.

### 모델 전용 트랙 완결

녹음 없이 확보한 결과:

1. 지연 분기 누출 — 51/51 그룹, 중앙값 2.03 dB (인과적이면 0.00)
2. 누출 > 의도한 효과 — 피치카토 future_leak 1.397 vs post_effect 0.662 (2.11배)
3. 누출비 — 피치카토 0.618 vs 지속음 0.059 (민감도 반론 기각)
4. 분기 후 조건이 분기 전 소리의 존재를 결정 — p 6/6, mf·f 0/6, p = 0.0041
5. 앞구간 누출 12.72 % (악보상 무음이어야 할 구간)
6. 단조성 위반 11.3 %
7. 강약이 음색을 바꾼다 — L2 정규화 후에도 C2ST 0.822 (VIOLET 에 유리)
8. 제어축 얽힘 — 피치카토·하모닉스를 키우면 다른 주법 쪽으로 이동
9. 생성 실패 4.29 %, 초기 latent 가 그룹째 결정

CEA / HCEL / CG 는 실연주 녹음을 기다린다.

## 개정 26 — 분기 전 창 길이 고정 (오프셋 확장의 전제)

분기 오프셋을 여러 값으로 넓히려면 창 정의를 먼저 고쳐야 한다. 창을
`[onset+0.04, branch−0.02]` 로 잡으면 오프셋이 커질수록 창이 길어져
**오프셋별 누출을 비교할 수 없다** — 다른 길이의 구간을 잰 값이기 때문이다.

`window_offset = min(branch_offset, REFERENCE_BRANCH_OFFSET_S)` 로 고정했다.
모든 조건이 항상 `[onset+0.04, onset+0.23]`(0.19 s)을 본다. 오프셋 0.25 에서는
기존과 완전히 동일하므로 개정 24·25 의 수치는 영향받지 않는다.
`prebranch_window_s` 열로 실제 창 길이를 기록해 분석기가 검증한다.

## 개정 27 — 지연 분기 확장 설계 (세 축)

기존 지연 실험은 **점 하나**였다: 오프셋 0.25 s, 주법 2개, w_cc 1.0.
결과는 강하지만 세 질문에 답하지 못한다. `src/viocf/delayed_sweep.py`.

### 축 1 — 분기 오프셋 0.25 / 0.50 / 1.00 / 1.75 / 3.00 s

인과적 생성기라면 **어떤 거리에서도** 0 이다. 거리와 무관하게 평평하면 조건이
창 전체에 박힌다는 뜻이고, "3 초 뒤에 일어날 일이 지금 소리에 이미 들어 있다"는
점 하나보다 훨씬 강한 진술이 된다. 음 길이를 4.0 → 6.0 s 로 늘려
오프셋 3.0 s 를 담는다(clip_seconds 10.0 안에 들어간다).

### 축 2 — 주법 부류 (3 대 3)

| 부류 | 주법 | 분기 시점 세기 변화 |
|---|---|---|
| sustained | sustain, legato_slur, tremolo | 활이 줄에 남아 **가능** |
| released | pizzicato, spiccato, staccato | 줄이 풀려 **불가능** |

지금까지는 n=1 대 n=1 이었다. 부류 안에서 반복되면 "한 주법이 끌고 간 것"이라는
반론이 막힌다.

### 축 3 — CC 유도 강도 w_cc ∈ {0.0, 1.0, 2.0}

"유도를 약하게 줘서 그런 것 아니냐"는 반론을 직접 잰다. 반대 가능성이 더
흥미롭다 — 세게 줄수록 조건이 창 전체에 강하게 박혀 **더** 샐 수 있다.
그렇다면 "손잡이를 세게 돌릴수록 덜 인과적이 된다"가 된다.
w_cc 는 샘플러 설정이라 값마다 별도 실행이 필요하므로 manifest 를 나눈다.

### 규모

6 주법 × 3 강약 × 5 오프셋 × 32 반복 = 2,880 클립/레벨 × 3 레벨 = **8,640 클립**
(4.35 s/클립 기준 약 10.4 시간). 조각 = (w_cc, 주법) 18개로 나눠 재개 가능.

`analysis_tier` 는 `generator_only_exploratory` 다 — 실연주 짝이 없으므로
헤드라인 지표(CEA/HCEL/CG)에 섞이지 않는다.

### 분석기 검증

`scripts/analyze_delayed_sweep.py` 를 정답 심은 세 시나리오로 확인했다:

| 심은 구조 | 먼쪽/가까운쪽 | 판정 | w_cc 판정 |
|---|---|---|---|
| 거리 무관 | 0.978 | 평평 (정답) | 무관 (정답) |
| 거리 감쇠 | 0.100 | 국소적 (정답) | 무관 (정답) |
| 유도 세면 악화 | 1.009 | 평평 (정답) | **더 샌다** (정답) |

주법 부류 대비는 Mann-Whitney U 로 낸다. 부류 안 주법별 값도 함께 출력해
한 주법이 끌고 가는지 확인할 수 있게 했다.

## 개정 28 — 인과적 기준 렌더러: 파이프라인 자체를 검증한다

지연 분기 결과의 핵심 주장은 "분기 전 spread 중앙값 2.03 dB, 인과적이면 0.00"이다.
당연한 반문이 붙는다 — **2.03 dB 가 측정 잡음이 아니라는 걸 어떻게 아는가?**

단위 테스트는 합성 파형 몇 개를 볼 뿐이다. 진짜 답은 **인과성이 보장된 렌더러로
같은 MIDI 를 렌더해 같은 파이프라인에 통과시키는 것**이다. `src/viocf/causal_reference.py`.

### 인과성이 어떻게 보장되는가

표본 n 은 시각 t_n 이하의 MIDI 사건만 참조한다. CC1 은 sample-and-hold(VIOLET 과
같은 방식)로 깔리고 **단측 IIR** 만 건다. 감쇠 주법은 시작 시점 CC1 로 감쇠가
정해지고 이후 변화에 반응하지 않는다 — 튕긴 줄은 손잡이를 돌려도 다시 안 커진다.

### 실측 결과

| 대조 | 그룹 | 동일 판정 | 중앙 spread | 최대 spread |
|---|---|---|---|---|
| causal (인과 보장) | 60 | **60 / 60** | **0.00000000 dB** | 0.000000 dB |
| leaky (0.6 s 미리 적용) | 60 | 0 / 60 | 13.141 dB | 13.141 dB |

**양성 대조**: 파이프라인이 없는 누출을 만들어내지 않는다.
**음성 대조**: 일부러 넣은 누출을 전부 잡아낸다. 검정력이 있다.

양성 대조만으로는 "아무것도 검출 못 하는 파이프라인"과 구분되지 않으므로 둘 다 필요하다.

### 이 과정에서 잡은 것 1 — 기준 렌더러 자신의 비인과 경로 2개

계약 검정(분기 전 비트 동일)이 처음에 실패했다. 원인이 둘이었다.

- **전역 peak 정규화** `out *= 0.98 / max(|out|)` — 최대값이 클립 전체에서 나오므로
  분기 이후 내용이 분기 이전 표본 크기를 바꾼다.
- **음 전체 평균 brightness** `mean(cc1[start:stop])` — 음이 분기를 가로지르면
  분기 이후 CC1 이 분기 이전 음색에 섞인다.

둘 다 우리가 VIOLET 에서 재고 있는 것과 **정확히 같은 종류**의 누출이다.
고정 이득과 표본별 시간가변 밝기로 바꿨고, 회귀 테스트 2개로 고정했다.

### 이 과정에서 잡은 것 2 — analysis_tier 필터가 모델 전용 검정까지 걸렀다

`run_metric_suite` 가 `analysis_tier == real_counterfactual_primary` 로 거른 뒤의
자료를 `delayed_branch_metrics` / `delayed_branch_strict_model_leak` 에 넘기고 있었다.

그 필터는 실연주 짝이 없는 행이 CEA/HCEL/CG 에 섞이는 것을 막으려는 것이다.
그런데 지연 분기 검정은 **설계상 실연주 기준선을 쓰지 않는다**(사람은 "250 ms
뒤부터 f" 를 연주할 수 없다). 거기까지 필터를 걸면 `generator_only_exploratory`
로 표시한 확장 스윕 8,640 클립이 통째로 사라진다 — 실제로 요약에 지연 블록이
아예 나오지 않았다.

tier 필터 **앞**의 자료(`model_scope`)를 두 함수에 넘기도록 고쳤다.
기존 expanded 지연 결과(51 그룹)는 `real_counterfactual_primary` 라 영향 없다.

⚠ 이 렌더러는 바이올린 음향 모형이 아니며 실연주 기준선(CEA/HCEL/CG)을 대신하지
않는다. 목적은 오직 측정 도구의 검증이다.

## 개정 29 — 음성 대조가 측정 창 밖에 떨어지고 있었다 (파이프라인은 정상)

전수(960 그룹) 인과 기준 검증 결과:

    [causal]  그룹 960  동일 960   중앙 spread 0.000000 dB   ✓
    [leaky]   그룹 960  동일 576   중앙 spread 0.000000 dB   ✗

양성 대조는 완벽했다. 음성 대조가 576개를 '동일'로 봤다.

**파이프라인 문제가 아니다. 대조 설계가 틀렸다.**

음성 대조는 CC1 을 `REFERENCE_LEAK_SECONDS = 0.6` 만큼 미리 당겼다. 그런데
측정 창은 `[onset+0.04, onset+0.23]` 로 고정이고(개정 26) 분기 오프셋은
0.25 ~ 3.00 s 로 넓다.

| 오프셋 | 분기 시각 | 0.6 s 당기면 | 창 안? |
|---|---|---|---|
| 0.25 | 1.00 | 0.40 | ✓ |
| 0.50 | 1.25 | 0.65 | ✓ |
| 1.00 | 1.75 | 1.15 | ✗ |
| 1.75 | 2.50 | 1.90 | ✗ |
| 3.00 | 3.75 | 3.15 | ✗ |

5개 중 2개만 창에 닿는다. 960 ÷ 5 = 192 그룹/오프셋이므로
검출 2 × 192 = **384**, '동일' 3 × 192 = **576**. **관측값과 정확히 일치한다.**
나머지 576 은 창 안에 넣은 것이 없었을 뿐 못 잡은 게 아니다.

**고침.** 클립마다 `branch_offset − LEAK_LANDS_AFTER_ONSET_S(0.10)` 만큼 당긴다.
그러면 주입 시점이 오프셋과 무관하게 항상 `onset+0.10`, 즉 창 한가운데가 된다.

실측 확인 (sustain, 그룹당 p vs f 의 창 내 최대 차이):

| 오프셋 | 당김 | causal | leaky |
|---|---|---|---|
| 0.25 | 0.15 | 0.00e+00 | 0.0595 |
| 0.50 | 0.40 | 0.00e+00 | 0.0595 |
| 1.00 | 0.90 | 0.00e+00 | 0.0595 |
| 1.75 | 1.65 | 0.00e+00 | 0.0595 |
| 3.00 | 2.90 | 0.00e+00 | 0.0595 |

**판정 출력도 고쳤다.** 전체 숫자 하나만 보면 '576 미검출'이 검정력 부족인지
대조 오류인지 구분되지 않는다. 이제 오프셋별로 쪼개 출력하고, 특정 오프셋이
통째로 '동일'이면 주입이 창 밖에 떨어진 것이라고 안내한다.

회귀 테스트 `test_negative_control_lands_inside_measurement_window` 가 오프셋
0.25 / 1.00 / 3.00 각각에서 causal = 0, leaky > 0 을 고정한다.

⚠ **양성 대조 960/960 은 그대로 유효하다.** 인과적 렌더러에서 파이프라인이
   없는 누출을 만들어내지 않는다는 것은 전수로 확인됐다. 이번에 틀린 것은
   "검출할 수 있는가"를 묻는 쪽 대조뿐이다.
